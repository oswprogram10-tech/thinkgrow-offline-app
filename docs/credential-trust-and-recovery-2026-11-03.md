# 자격 신뢰·시각 동기화·계정 복구 — 2026-11-03

이 문서는 기기 등록 뒤 자격 서명키 변경, 시계 되돌림, PIN 변경의 현재 동작과 아직 필요한 복구 범위를 기록한다. 실제 키 교체나 서버 설정 변경은 수행하지 않았다.

## 발급키 신뢰와 교체

`release/native-policy.json`의 `credential_keys`는 새 자격과 저장된 자격·수업 서명을 확인할 공개키 목록이다. `credential_signing_key_ids`는 새 등록·갱신 자격에 사용할 수 있는 키 ID이며, 반드시 공개키 목록의 부분집합이어야 한다. 은퇴한 키 ID는 저장된 자격과 수업 판본 검증을 위해 신뢰 목록에 남길 수 있고, 활성 목록에서는 제거할 수 있다.

교체 순서는 새 공개키와 새 ID를 신뢰·활성 목록에 기존 ID와 함께 넣은 앱을 먼저 배포하고, 그 뒤 서버 발급 키 ID를 새 키로 바꾸는 방식이다. 서버가 새 키로만 서명하게 된 뒤 후속 앱 정책에서 이전 ID를 활성 목록에서 뺄 수 있다. 이전 공개키는 그 키로 서명한 저장 자료를 읽을 수 있도록 신뢰 목록에 보존한다. 이 저장소에는 현재 `offline-credential-20261103`만 활성화되어 있으며 실제 키 교체, 키 생성, Secret Manager 변경, 배포는 하지 않았다. 개인키는 이 저장소에 넣지 않는다.

## 신뢰 시각

발급키가 활성 목록에 있는 서명 자격은 서명·역할·기기·유효 기간을 검증한다. 더 높은 epoch의 새 자격은 서명된 `issued_ms`로 저장소의 시간 high-water를 다시 고정한다. 같은 epoch의 기존 자격은 신뢰 시각을 갱신하지 않는다. 현재 실행 중에는 서명 시각과 monotonic 경과 시간을 기준으로 되돌림을 막고, 앞으로 이동한 시스템 시각도 함께 반영한다.

앱을 다시 시작하면 OS의 벽시계로 시작한다. 저장된 시간보다 시계가 뒤로 가 있으면 계정은 읽기·복구 전용이 된다. 서버가 새 epoch 자격을 발급하면 서명된 시각으로 다시 동기화할 수 있으며, 캐시된 오래된 자격만으로는 잠금을 풀지 않는다. 시각 불확실성은 초안·제출 대기열·첨부를 삭제하지 않는다. 이 방식은 재부팅 사이의 하드웨어 보안 시계를 제공하지 않는다.

## PIN과 보호 백업

현재 PIN을 확인한 뒤 PIN을 바꾸는 경로가 교사·학생·학부모 앱에 연결됐다. 새 Argon2id salt와 암호문을 원자 교체하고 데이터 키·기기 키·계정 DB는 유지한다. 변경이 끝나면 계정을 잠그고 새 PIN으로 다시 연다.

암호화 `.tgbak` 백업은 보호된 계정 비밀, 일관된 SQLite core/lessons snapshot, 첨부 파일을 포함한다. 12자 이상 백업 암호에서 Argon2id 키를 만들고 AES-256-GCM으로 봉인한다. 총 원본 저장 데이터는 최대 32 MiB다. 초과하면 백업을 만들지 않고 기존 자료를 보존한다. 내보내기 때 백업 암호를 이 기기의 PIN 복구용 복구 키로도 봉인한다. PIN 복구는 기존 백업을 만든 계정에서만 가능하며, 계정 DB를 덮어쓰지 않는다.

다른 기기에 복원하면 OS 보호 저장소와 새 PIN으로 vault를 다시 봉인하되 기존 device ID·서명키를 유지한다. 복원 뒤 새 등록 코드를 사용하면 서버가 더 높은 epoch를 발급한다. 온라인 기준 구현의 `OfflineDeviceService.redeem`은 동일 기기에 새 코드를 발급하고 이전 코드의 epoch 재사용을 거부하는 경로를 포함한다(`thinkgrow-platform-integration/cloud/offline_devices.py`, `tests/test_offline_devices.py`). 새 코드 행의 바인딩에 같은 request ID를 다시 쓰는 것도 서버 로직상 허용된다. 서버가 epoch를 확인하는 경로는 이전 epoch 자격을 거부한다. 기존 기기가 오프라인이면 그 기기의 로컬 사용을 원격으로 멈출 수 없다. 제출 수신 어댑터가 아직 없으므로 전체 온라인 데이터 흐름에서의 fencing은 완료로 주장하지 않는다. 백업 파일은 같은 역할 앱에만 복원하며 설치 게임 모듈은 포함하지 않는다.

## 이번 변경의 검증 범위

Windows에서 `cargo test --locked -p thinkgrow-offline-core` 47개(새 백업 암호화·역할 경계, PIN 변경·복구, 타기기 복원·epoch 갱신 통합 포함), 교사·학생·학부모 `cargo check`, UI 3역할 빌드, 계정 UI 합성 검사 6개, 릴리스 브리지 검사 12개를 통과했다. `tools/verify_offline_core.py`도 모든 단계를 통과했다. 상세 결과는 [검증 기록](build-evidence/offline-core-2026-11-03.json)이다.

실기기 복원과 실제 사용자 PIN 변경/복구, Android/iOS 재검증, 발급키 교체는 수행하지 않았다. 온라인 전용 등록 API와 Hosting은 읽기 전용으로 확인했으며 등록 기능이 활성화되고 설치 파일 공개는 계속 꺼져 있다. 배포 소스 SHA-256이 운영 기록과 일치해 새 서버 업로드는 필요하지 않았다.
