# 수업 자료 스토어 및 앱 실행 계획

작성일: 2026-11-03
상태: 요구 범위 초안. 구현은 아직 시작하지 않음.

## 1. 목표

온라인 마켓플레이스에 **수업 자료** 유형을 추가해 교사가 문서·미디어·애플리케이션을 올리고, 로그인한 교사들이 찾아 내려받도록 한다. 오프라인 앱에는 승인 자료를 필요한 기기에 보관하는 자료 보관함을 제공한다.

게임과 애플리케이션은 내려받기·설치와 실행 자격을 분리한다. 오프라인 실행을 지원하는 자료는 연결 없이 실행하고, 온라인 연결이 필요한 자료는 설치해 둘 수 있지만 유효한 서버 연결과 세션이 없으면 실행하지 않는다.

## 2. 확정된 요구

- 온라인 마켓플레이스의 최상위 자료 유형은 `전체`, `문항`, `게임`, `수업 자료`로 둔다.
- `수업 자료` 안에서만 아래 하위 유형을 선택한다.
  - PDF
  - 한글 파일
  - PPT
  - 동영상
  - 음악
  - 애플리케이션
- 수업 자료 공개 범위는 **로그인한 교사 전체**다.
- 애플리케이션은 **웹 앱과 검토된 설치 파일**을 포함한다.
- 게임과 문항은 기존 마켓 유형으로 유지한다. 수업 자료 하위 유형에 중복해서 넣지 않는다.
- 정식 실기기 검증은 이번 범위에서 제외한다. 자동 검증, 브라우저 합성 검증, 빌드 근거는 기록한다.

## 3. 현재 구조와 변경점

온라인 마켓플레이스에는 현재 `전체·문항·게임` 탭이 있다. 공유 화면은 문항·문항 묶음과 자작 게임 게시 흐름으로 나뉜다. 오프라인 교사용 앱에는 채점과 게임 보관함이 있으며, 일반 수업 자료 보관함은 없다.

현재 오프라인 게임 설치 경로는 설치 단계에서 `offline.solo`와 `host_api: 1` 계약을 요구한다. 그래서 승인 게임을 목록에서 볼 수 있어도 계약을 만족하지 않으면 설치와 수업 배정이 거절된다. 로컬 게임 호스트도 외부 네트워크 연결을 허용하지 않는다.

변경 후에는 다음 세 판단을 별도로 저장하고 적용한다.

1. **스토어 승인:** 게시·다운로드 가능한가?
2. **설치 가능성:** 이 계정과 기기가 파일을 보관할 수 있는가?
3. **실행 가능성:** 지금 오프라인 실행 또는 온라인 서버 실행이 가능한가?

## 4. 수업 자료 업로드·스토어

### 교사 업로드 흐름

1. `수업 자료` 탭에서 하위 유형을 선택한다.
2. 파일을 고르고 제목, 설명, 교과·학년·단원·태그를 입력한다.
3. 권리 보유, 학생 개인정보 미포함, 공유 범위를 확인한다.
4. 업로드 서비스가 확장자, 실제 MIME/파일 시그니처, 크기, 해시, 악성 파일 여부를 검사한다.
5. 검사를 통과한 자료만 로그인 교사 전체 검색 결과에 게시한다. 애플리케이션은 별도 검토 승인을 필수로 한다.

### 자료 유형별 1차 동작

| 하위 유형 | 제안 형식 | 1차 제공 방식 |
|---|---|---|
| PDF | `.pdf` | 안전한 앱 미리보기와 내려받기 |
| 한글 파일 | `.hwp`, `.hwpx` | 내려받기 후 기기에 연결된 편집기로 열기. 브라우저 미리보기는 별도 검토 |
| PPT | `.ppt`, `.pptx` | 내려받기 후 연결된 편집기로 열기. 브라우저 미리보기는 별도 검토 |
| 동영상 | 허용 코덱을 정한 비디오 형식 | 승인된 플레이어에서 재생, 필요한 경우 암호화 보관함에 내려받기 |
| 음악 | 허용 코덱을 정한 오디오 형식 | 승인된 플레이어에서 재생, 필요한 경우 암호화 보관함에 내려받기 |
| 애플리케이션 | 웹 앱 또는 검토된 설치 파일 | 아래 실행·설치 정책 적용 |

실제 확장자와 유형별 최대 용량은 구현 전에 확정한다. 매크로와 실행 콘텐츠가 포함된 문서 형식은 기본적으로 거부하거나 별도 검토 대상으로 보낸다. HWP/PPT 미리보기 변환은 원본을 바꾸지 않고, 변환 품질·개인정보 처리·라이선스를 확인한 뒤 별도 단계로 추가한다.

### 서버 데이터와 업로드 검토

- 파일 본문은 비공개 Cloud Storage에 버전·SHA-256별로 보관하고 Firestore에는 검색 메타데이터와 승인 상태를 둔다.
- 업로드는 임시 격리 영역으로 받고 검사가 끝난 뒤 게시 영역으로 승격한다. 큰 동영상 파일은 API JSON 응답에 넣지 않고 재개 가능한 청크 전송으로 처리한다.
- 자료 상태는 `초안 → 검사/검토 대기 → 게시 → 철회`로 관리한다. 철회는 신규 검색·다운로드를 막고 기존 기기 사본이 원격 삭제된다고 표시하지 않는다.
- 일반 문서·미디어는 파일 시그니처, 악성 파일 검사, 권리·개인정보 확인을 적용한다. 애플리케이션은 추가로 독립 검토를 거쳐야 게시된다.
- 학생에게 자료를 전달하는 경로는 교사의 수업 배정으로 제한한다. 학생 계정이 전체 교사 스토어에서 자료를 직접 내려받지는 않는다. 학부모 앱은 1차 범위에서 스토어 업로드·설치를 제공하지 않는다.

## 5. 오프라인 앱의 자료 보관함

- 교사 앱에 `수업 자료` 탐색·다운로드 화면을 추가한다. 로그인 교사는 승인된 자료를 검색하고 기기에 저장할 수 있다.
- 교사는 수업 자료를 특정 수업에 배정한다. 학생 앱은 자신에게 배정된 자료와 그 고정 판본만 내려받는다.
- 대용량 파일 전송은 기존 역할 자료 교환 응답에 얹지 않고, 기기 서명 자격으로 보호되는 전용 청크 업로드/다운로드 API를 둔다. 마지막 청크에서 전체 해시를 검증하고 이어받기 상태를 보관한다.
- 로컬 파일은 계정별 암호화 보관함에 둔다. PDF·미디어는 앱에서 읽을 수 있게 하고, HWP·PPT·설치 파일은 사용자가 명시적으로 선택할 때 OS의 연결 앱이나 설치 화면으로 넘긴다. 임시 복호화 파일은 작업 완료·잠금 시 정리한다.
- 자격 만료 시 저장 파일과 초안은 보존한다. 만료 후 새 다운로드·배정은 막고, 기존 자료는 허용된 읽기·복구 정책을 따른다.

## 6. 앱 스토어 설치·실행 정책

### 공통 메타데이터

각 게임·애플리케이션 판본은 다음을 선언하고 서버 검토에 결속한다.

- 실행 종류: 정적 웹 앱, 온라인 웹 앱, 서버형 서비스, OS 설치 프로그램
- 네트워크 요구: 오프라인 실행 가능 또는 온라인 연결 필요
- 지원 OS·앱 버전, 시작 경로, 패키지 해시와 서명 정보
- 필요한 권한과 허용된 서버 출처 목록
- 검토 상태와 폐기·업데이트 상태

선언은 검증 근거와 함께 승인되어야 한다. 앱은 임의 출처·앱 쿠키·Tauri 권한·계정 키를 게임에 넘기지 않는다.

### 설치 및 실행

- **오프라인 게임/웹 앱:** 현재의 격리된 로컬 호스트에서 실행한다. 설치 후 네트워크 없이도 파일과 체크포인트가 동작하는지 검증한다.
- **온라인 웹 앱/게임:** 설치를 허용한다. 실행할 때 승인된 도메인과 전용 서버 세션을 확인하고, 검증된 연결이 없으면 `인터넷 연결 필요` 상태로 실행을 막는다. `navigator.onLine` 값만으로 연결 성공을 판정하지 않는다.
- **서버형 게임:** 기기에 서버를 설치하지 않는다. 승인된 온라인 실행 서비스에 단기 실행권으로 접속하는 런처 항목으로 제공한다. 서버가 준비되지 않았거나 연결이 끊기면 시작하지 않는다.
- **검토된 OS 설치 파일:** 파일을 먼저 내려받고 서명·해시·OS 호환성을 확인한다. 실제 설치는 사용자가 선택한 뒤 운영체제의 설치 확인 절차로 넘기며 앱이 몰래 설치하거나 실행하지 않는다.
- **학생 배정:** 교사 배정은 게임/앱 ID와 SHA-256 판본에 고정한다. 학생은 배정된 판본만 설치할 수 있고 원본 판본이 바뀌면 새 배정을 요구한다.
- **진행 기록:** 오프라인 게임 이벤트·체크포인트는 기존 로컬 기록 방식으로 보관한다. 자체 보고 점수는 공식 평가로 취급하지 않는다. 교사 서버로 진행 기록을 보내는 기능은 별도 동의·권한·데이터 계약 후 추가한다.

온라인 실행을 지원하려면 CSP에 임의 인터넷을 허용하지 말고, 검토된 게임별 출처 목록과 단기 권한을 사용한다. 온라인 게임과 로컬 호스트는 서로 다른 실행 정책을 유지한다.

## 7. 구현 단계와 완료 기준

### 0단계 — 입력 형식·정책 확정

- 하위 유형별 확장자, MIME, 최대 용량, 영상·음성 코덱을 표로 확정한다.
- HWP/HWPX·PPT/PPTX를 앱에서 미리보기할지, OS 앱으로 열지 정한다.
- 일반 파일 검사와 애플리케이션 독립 검토자의 책임·승인 기준을 정한다.
- 초기 설치 파일 OS 범위와 코드 서명 요건을 정한다.

**완료 기준:** 업로드 허용표, 크기 제한표, 검토 체크리스트, 앱별 지원 OS 표가 승인된다.

### 1단계 — 온라인 자료 도메인과 안전한 전송

- `class_materials` 자료 모델, 비공개 버킷 구조, 버전·해시·검토 상태를 추가한다.
- 권한이 있는 교사의 재개 가능한 청크 업로드/다운로드, 격리·검사·철회 API를 추가한다.
- 교사 전체 공개 목록은 승인된 판본만 포함하고, 다운로드 때마다 권한·게시 상태를 다시 확인한다.
- 백업·복원에서 원본 파일 무결성을 검증하고, 복원만으로 게시·앱 권한이 되살아나지 않게 한다.

**완료 기준:** 합성 파일로 크기 초과, MIME 불일치, 해시 변조, 악성 검사 실패, 중단 후 이어받기, 철회 뒤 재다운로드 차단을 확인한다.

### 2단계 — 마켓플레이스 수업 자료 탭

- `전체·문항·게임·수업 자료` 탭, 하위 유형 필터, 제목·교과·학년·태그 검색을 추가한다.
- `자료 공유하기`에 유형별 업로드 폼, 권리·개인정보 선언, 검토 상태와 미리보기/다운로드를 추가한다.
- 로그인 교사만 게시·열람할 수 있고 게시 전 자료가 검색에 나타나지 않는지 확인한다.

**완료 기준:** 6개 하위 유형마다 업로드, 검색, 상세, 다운로드, 게시 철회를 끝까지 검증한다.

### 3단계 — 앱의 수업 자료 보관함

- 교사 앱 탐색·저장·수업 배정, 학생 앱의 배정 자료 내려받기·읽기를 구현한다.
- 계정별 암호화 저장, 이어받기, 해시 확인, 만료·잠금 후 보존, 안전한 OS 열기 흐름을 연결한다.
- 화면에는 용량·파일 유형·판본·마지막 동기화·오프라인 이용 상태를 표시한다.

**완료 기준:** 학생이 미배정 자료를 받을 수 없고, 네트워크 중단·계정 잠금 뒤에도 기존 자료의 정책상 이용이 보존된다.

### 4단계 — 온라인 전용 앱과 게임 분리

- 설치 검증에서 오프라인 계약 요구를 분리해, 승인된 온라인 전용 항목도 저장할 수 있게 한다.
- 온라인 실행권 발급, 출처 허용 목록, 연결·세션 확인, 오프라인 차단 화면을 추가한다.
- 서버형 런처와 OS 설치 파일은 각기 다른 승인·실행 경로로 처리한다.
- 기존 오프라인 호스트의 CSP·로컬 파일 접근 경계를 유지한다.

**완료 기준:** 온라인 전용 앱은 설치되지만 연결을 끊으면 실행이 거절되고, 연결 복구 뒤 유효 세션으로 실행된다. 오프라인 게임은 외부 통신 없이 실행된다. 설치 파일은 사용자의 OS 확인 없이 실행되지 않는다.

### 5단계 — 회귀 검증과 배포

- 단위/API/UI 합성 검증, Windows·Android 빌드, 업로드/다운로드 무결성, 접근 통제와 회귀 검증을 수행한다.
- 승인된 합성 자료로 스테이징을 거친 뒤 Firebase Hosting·전용 오프라인 API에 배포한다. 기존 온라인 메인 API의 트래픽·운영 상태를 분리 검증한다.
- 사용자가 요청한 대로 실기기 검증은 이 완료 기준에 포함하지 않고, 미수행 범위를 배포 기록에 명시한다.

## 8. 구현 전 남은 결정

다음 값은 현재 저장소에서 정해진 일관된 정책을 찾지 못해 초안 기본값으로 남긴다.

1. **구체 확장자·용량:** 우선안은 PDF/HWP/HWPX/PPT/PPTX, 동영상 MP4·WebM, 음악 MP3·M4A·WAV·OGG다. 비디오·오디오·설치 파일의 유형별 최대 용량은 서버 전송·저장 예산을 보고 정한다.
2. **학생 배포:** 기본안은 교사가 수업에 배정한 뒤 학생 앱에서만 내려받게 하는 것이다. 모든 학생에게 공개하는 별도 자료실은 범위에 넣지 않는다.
3. **일반 문서 검토:** 기본안은 자동 파일 검사와 교사 권리·개인정보 확인을 필수로 하고, 실행 가능한 앱은 사람의 독립 검토와 서명 확인을 필수로 하는 것이다.
4. **OS 설치 파일:** 초기 후보는 Windows와 Android이며, 각 OS에서 서명·설치 경로가 확인된 형식만 허용한다. Apple 빌드·배포 경로는 해당 타깃 검증 뒤 정한다.
5. **미리보기·백업:** HWP/PPT 변환 미리보기와 대용량 미디어의 보호 백업 포함 여부는 용량·라이선스·암호화 파일 처리 설계를 확정한 뒤 정한다.

## 9. 의존성과 제약

- 현재 오프라인 역할 교환은 응답 크기에 제한이 있어 대용량 파일 전송에 사용할 수 없다. 전용 청크 전송과 저장소 정책이 선행되어야 한다.
- 마켓플레이스 현재 자료 유형은 문항·게임이므로 새 자료 유형의 API·스토리지·백업 범위를 추가해야 한다.
- 온라인 실행은 네트워크 연결 확인만으로 완료되지 않는다. 게임별 서버 출처, 인증, 권한과 실행 세션 계약이 필요하다.
- 실행 파일은 파일 다운로드와 앱 실행 권한을 별도로 검토해야 한다. 승인 전 공개·실행을 막고 플랫폼별 OS 확인 절차를 사용한다.
- 이 계획은 기능·데이터·보안 작업의 설계 초안이다. 코드를 수정하거나 테스트·배포하지 않았다.
